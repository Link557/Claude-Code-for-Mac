# Windows 桌面端模块边界审查

审查基于 2026-11-10 工作区，包含当时未提交的修改。接入和用量功能仍在实施，最终行为以交付验证为准。

## CLI 接入与缓存

- `nativeRuntime.ts` 按手动路径、系统路径和用户目录解析 CLI；`sdk.ts` 通过它为临时查询和新建会话提供可执行文件；`connection.ts` 负责版本、认证检测和官方登录入口。运行中的 `LiveSession` 持有已启动的查询，新路径只影响之后启动的进程。
- `meta.ts` 的模型缓存按工作目录、CLI 文件及配置指纹区分；`CommandCatalog` 独立管理命令快照、刷新和迟到结果，但原先 `ipc.ts` 的命令配置仅包含手动路径和应用版本。自动发现的 CLI 在相同路径替换时，旧命令缓存和旧进程事件可能被误认为当前结果。模型和命令应共用 `cliIdentity.ts` 的文件标识，并在安装、路径变化及回焦发现替换时刷新；已有会话无需关闭。
- `ipc.ts` 是接入、缓存和会话的组合处，适合统一触发失效；安装流程应通过接入模块暴露状态，界面只依赖共享 IPC 契约，不解析安装器或 SDK 输出。
- 与远端 `win.23` 合并后，命令目录身份已包含 CLI 文件、用户及项目配置文件标记和相关环境标记；变更配置时失效旧目录，并拒绝旧会话的迟到发布。CLI 基准在设置 `userData` 后初始化，避免启动时从默认目录缓存错误设置。接入状态订阅相关配置变更，认证的已登录、未登录、未知三种结果独立于项目供应商检测错误。

## 模型目录与实际模型

- `metadataQuery.ts` 从临时 SDK 查询取得目录，并由 `fableMapping.ts` 和 `fableCatalog.ts` 处理别名；`meta.ts` 转换为共享的 `ModelOption`。`LiveSession.ts` 用所选值启动或切换模型，运行时模型来自 CLI 事件，两者属于目录和实际运行状态，不能相互替代。
- Fable 的目录映射和统计分类分别服务于选择和历史分析；应分别以 CLI 目录及历史记录中的实际模型 ID 为依据。新模型命名变化需要同时检查这两处规则，避免从展示名称推断实际用量。

## 会话历史与用量

- `sessions.ts` 通过 SDK 列表和本地编辑映射提供会话摘要；`SessionManager.ts` 通过 SDK 读取历史并管理运行中快照，外部变更同步会保护忙碌会话及排队操作。`transcript.ts` 将实时和历史消息转换为界面消息。
- `usageAnalytics.ts` 独立读取 CLI 的 JSONL 用量字段，在 worker 中建立按文件的派生索引，再通过共享统计类型交给页面；`usage.ts` 则查询套餐额度。两条数据路径用途不同，统计页应明确保留各自的加载和失败状态。
- 历史解析存在 SDK 消息适配和 JSONL 用量适配两处边界；后者保留模型、Token 和时间等统计必要字段，不依赖界面转录。CLI 格式变化时需分别验证历史显示与统计，避免把其中一处的成功当作另一处的验收。
